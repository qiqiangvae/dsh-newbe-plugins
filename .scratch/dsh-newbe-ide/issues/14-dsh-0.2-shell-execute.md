# 14: 适配 DSH 0.2.0 的 shell 契约（`start` 已被 `execute` 取代）

**Status:** resolved

**要解决的问题:** 面板在 DSH 0.2.0 上**点一次启动就报错**，进程根本起不来。

**根因（实测，非推测）:** DSH 0.2.0 起 `ShellExecutor` 只留 `execute(spec)`，`start` 已从契约里删掉：

```
$ dsh --version
0.2.0-rc.2

$ node -e "…LocalBashExecutor.prototype…"
LocalBashExecutor.prototype: constructor, execute, executeArgv, onProcessDone, resolve, spawnSpec
start: undefined | execute: function | resolve: function
```

`runtime.ts` 里 `await shell.start(resolved)` 于是拿到 `TypeError: shell.start is not a function`，
被 `start()` 的 catch 收成 `run.error`，面板显示「启动失败」。
（`dsh-shell` 的 `ShellProcess` 文档注释里"returned by `ShellExecutor.start`"是**没跟上改名的旧注释**，
照着它找方法会白找。）

## 改了什么

- `src/runtime.ts`：新增 `launch()`，`shell.execute ?? shell.start` 都试（分离调用，原型方法直接取会丢 `this`）；
  两个都不在时给一句人话错误，不再抛 TypeError。`ShellServiceLike` 同步声明 `execute?` / `start?`。
- `src/runtime.ts`：`resolve()` 请求里加 **`onExpiry: 'none'`**（见下），`RunSpec` 的调用面不变。
- `test/runtime.test.mjs`：新增三条断言——只有 `execute` 的假 shell 也能起（DSH 0.2.0 形态）、
  `onExpiry === 'none'`、两个方法都没有时给可读错误。

## `onExpiry` 为什么必须显式给 `'none'`（同一代的第二个坑）

`dsh-bash-local` 的 resolve 是 `onExpiry: request.onExpiry ?? "kill"`，默认 `timeoutMs` = 120 s（上限 600 s）。
面板启的是 dev server，不显式给 `'none'` 就会"跑两分钟自己没了"，而且按 `killed` 记账会误报成「启动失败」。
真机对照（同一个 `timeoutMs: 100`，走真实 `LocalBashExecutor`）：

```
A onExpiry=none  → completed 0 "survived"     # 活过 100 ms 那个截止
B onExpiry=kill  → killed null delta: ""      # 对照组：默认截止把它杀掉
C running        → running | kill(): true     # 长驻进程：句柄可停，停下来记 killed
```

## Comments

**为什么不干脆只留 `execute`**：0.1.x 的 `start` 仍是已发布版本的活路径（插件 npm 上的版本对应用户手上的
DSH 版本），`?? ` 一个表达式就能两代都跑，删掉是白丢兼容面。代价是假 shell 测试要覆盖两形态——已经加了。

**没有改版本号**：按仓库规则 `main` 上不 bump 版本、不打包；发版走通道分支（见根 `AGENTS.md`）。

**真机实测怎么做的**（没有重启用户的 `dsh web`）：临时目录里 `ctx.plugin(LocalSubprocessRuntime)` +
`ctx.plugin(LocalBashExecutor)`，直接从全局安装的 `@deepseek-ai/dsh-*` 里 import，
拿到 `ctx.shell` 后按插件的调用序列走一遍。探针脚本用完即删。

**2026-10-27 用户在 0.2.1-rc.3 上复报**：桌面 profile（`~/.dsh/profiles/desktop`）装的是 npm 上的
`dsh-newbe-ide@0.4.1`，代码还是 `shell.start(...)`；DSH 桌面升到 `0.2.1-rc.3` 后点启动即报
`shell.start is not a function`。修复其实已在仓库里（0.2.0-rc.2 时写的），只是没发 npm，桌面 profile 吃不到。
在 `0.2.1-rc.3` 的真实宿主上重跑同一条探针：`start: undefined | execute: function`，旧调用抛同样的
TypeError；修好的 `launch()` 起进程 → 增量读输出 → 长驻进程 `stop()` → 状态 `stopped` 全部通过。
随本票发 `0.4.2-alpha` / `0.4.2`，桌面 profile 显式装 `0.4.2`。
