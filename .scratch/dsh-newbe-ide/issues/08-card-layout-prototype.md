# 08: 控制区改成卡片布局（变体 C 已定稿）

**What to build:** 面板控制区过去是五行 chrome，且"一条启动配置"被拆在三处：二级 tab 只有状态点、启停键在最右边、命令另起一行、过滤条再一行。配置一多，眼睛要在三行之间对齐同一个名字。改成卡片布局：一条配置的状态与操作收进同一个容器。

**Blocked by:** 04（一个项目多条启动配置：两层 tab）

**Status:** ready-for-human（变体 C 已折进 `src/client.tsx`，真机验证通过）

**决定: 变体 C 主从卡片。** 左列 224px 竖排这个项目的启动配置（状态点 / 名称 / 端口 / 状态或运行时长），右列是选中那条的详情：状态·端口·运行时长·退出码 指标块、启动·停止·重启、启动命令、日志过滤条。选它的理由：配置多了是纵向滚而不是横向挤，当前配置的数值一眼可见，且每条配置的操作与它自己的状态在同一张卡里。

原型期的三个变体（记录在案，均已删除）：

| 变体 | 结构 | 为何没选 |
| --- | --- | --- |
| A 配置卡片条 | 一条配置一张卡，卡内自带启停键；命令与过滤各占一条窄行 | 配置多了要横向滑，同屏可见条数有限 |
| B 单卡控制台 | 控制区只剩一张卡，配置改下拉 | 纵向最省，但看不到"还有哪条在跑" |
| C 主从卡片 | 左列配置列表 + 右列详情 | 选中 |

## Comments

**定稿记录（2026-09-12）**

- 折进去的是 `src/client.tsx` 里 `IdeView` 的项目分支，新样式类 `ide-master` / `ide-mlist` / `ide-mhead` / `ide-mitem` / `ide-mstate` / `ide-madd` / `ide-detail` / `ide-dhead` / `ide-dmeter` / `ide-metric` / `ide-dactions` / `ide-dcmd`；原型专用的 `proto-*` 样式、`prototype-cards.tsx`、`?variant=` 开关、底部的切换胶囊与 `卡片布局` 入口按钮全部删除。
- 随之作废的旧类：`ide-subrow` / `ide-subtab`（二级 tab 行）、`ide-cmdline` / `ide-path`（身份行）、`ide-toolbar` 里控制行用法（该类仍被配置块使用）。`ide-cmd` 改成单行省略（原来 `word-break:break-all`，两行高度会让卡片高度跳动）。
- 「项目身份行」被并进左列卡头（项目名 + 路径），因为上面的一级 tab 已经写过一遍项目名。
- 状态文案仍是 `describeRun` 一份：指标块直接吃它的返回值（"运行中/已停止/已退出（码 N）/启动失败：…"），没有再写一套短词表；左列每行的状态也是同一个函数（`title` 里给全文）。运行中时左列显示运行时长代替状态词。
- 顺手补了一个洞：项目**没有**任何启动配置时，旧实现里 `⚙ 配置` 按钮不渲染（它跟着控制行走），只剩一行"点「⚙ 配置」添加"的死胡同；现在这种项目在右侧详情位渲染提示 + `⚙ 配置` 按钮，配置块（含从 IDEA 导入）始终可达。

- `pnpm run typecheck` / `pnpm run check` / `pnpm run test`（77 条）全绿；`lib/client.js` 已重建（宿主直接换 rev 发新包，无需重启 `dsh web`）。
