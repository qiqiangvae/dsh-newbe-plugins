# 12: 日志体验——内存、检索与人性化（设计共识记录）

**要解决的问题:** 大量日志下（单配置累计 10 万行、峰值约 2000 行/秒、连续 8 小时）日志区既卡又难用。两个诉求：资源消耗与人性化。

**已定的指标（Q3′）:**

1. **往回滚能覆盖本次运行的全部输出**（靠磁盘分页，不靠全量常驻）；
2. **追加时交互 p95 < 100ms、单帧 < 16ms**；
3. **常驻内存 ≤ 15MB/配置**（现状 1–1.5MB，允许涨 10 倍换检索能力），多配置总账 ≤ 30MB。
   内存是**护栏**不是靶子：实测（5 个 spool 文件、2,771 行）均值 145.68 B/行、p99 695 B、最大 975 B、**零条超 2 KiB**，现有实现已远低于预算——真正的成本是检索上限、每 tick 的 O(n) 抖动、宿主读放大。

## 已定决策（按层）

**语义 / 模型**

- 真相源：进程输出 → 宿主 ring（真环形）→ 磁盘 spool；浏览器只持**常驻窗口**，更早的靠**分页**从 spool 往回读。
- 常驻窗口 **≈ 2 万行**；分页 **字节窗口 256 KiB**（实测均值下 ≈ 1,800 行）、**距顶 50 行预取**、**最多常驻 5 页**（超出淘汰最老一页）。
- 读到轮转边界（`.1` 代开头，上限约 11.5 万行）**必须明说**"更早的输出已被轮转丢弃"，不许静默截断。
- **行号 = 我们的绝对序号**（跨分页稳定；与磁盘文件行号无关）。
- 只驻留**选中配置**的日志；其它配置靠总览卡片（状态点/端口/时长/最后一行）+ **错误计数徽章**。
- **日志永不自动进模型上下文**（插件卖点与隐私边界）；将来若要给 Agent 看，必须是用户点一下的显式一次性动作。

**宿主侧**

- 预算：**单配置 ≤5% 单核、每配置读次数 ≤2 次/秒**（现状 5.25，选中那个 6.5）。**但不能靠放大 pump 间隔去凑**：DSH shell 每个流只有 64,000 B 内存尾窗（实测均值 145.68 B/行 ≈ 439 行），窗口溢出即丢输出——250ms 对应约 1,750 行/秒的安全线，500ms 掉到约 880 行/秒，比假设峰值还低。所以第 1 步走的是「去掉重复采集」（`snapshots()` 不再顺手 drain），不是放大间隔；要再往下降，得让宿主知道「哪个配置正在被看」（协议层，第 2/3 步）。
- 三个动作：客户端**按配置记 offset**（切回来不再整段重发 ≤5,000 行 ≈ 728 KB）；`runs()` **不再每 tick 抽干所有 run**；ring 换**真环形缓冲**（现在是 `push` + `splice(0,drop)`，饱和时每行搬移约 5,000 槽）。
- 不动：写盘已经是"每 drain 批量 `appendFileSync`"，合格。
- 防御：`lossy` 键缺失时视为**未知**（本 profile 挂的是 `dsh-bash-sandbox`，`{delta, lossy}` 契约成立，但换到 terminal-bash 就没有这个键）。

**客户端 / 渲染**

- **虚拟化**（窗口化渲染）：见下面「虚拟化与交互（已定）」。
- `shown` 用 `useMemo`；列表 key 换**稳定行身份**（绝对序号），不再用数组下标（现在是滑动尾窗 + index key ⇒ 每次追加最多 2,000 次文本改写）。
- 软换行（不横向滚）；**极端单行安全阀**（>8KB 折叠可展开）——不为"超长行"做专题，实测没有这种行。
- 不加我们自己的时间戳列。
- **不做**：TerminalBlock（可达但是头尾截断 + 展开即全渲染，不是虚拟化）；primitives 外壳（剪贴板需求取消后边际收益小于垫片+漂移守护的成本）。
- 等级**入行时算一次**并随行保存；关键字输入 **150ms 防抖**；**不上 Worker**（2 万行的字符串匹配不值得线程与序列化）。
- **跳错误**：识别并折叠 stack trace 块（`at …` / `Caused by:` / `… N more` / 缩进行），加"首个/末个 ERROR"跳转。不做错误聚合、不做失败摘要区。
- ANSI 颜色：**不为它改宿主管线**（整行等级着色已够）；若选中的组件顺带支持，留开关但默认关。

**明确不做（本轮）**

- **日志导出与复制**：下载文件、复制过滤结果、复制文件路径，全部不做——面板只负责看，往外拿自己开磁盘上那个文件。
- 多配置同屏并排（只做错误计数徽章）。
- 错误聚合、失败摘要区、选择多行复制。

**先行提交（Q13，独立于架构改动）**

① `shown` memo；② 稳定 key；③ 把 `setFromHistory/setTruncated` 移出 state updater；④ offset 按配置记；⑤ `runs()` 降频/去抽干；⑥ 宿主 ring 换真环形。每步用现有 78 条测试 + 面板回归脚本（`.scratch/dsh-newbe-ide/repro/run-jump-check.sh`）验证。

## 虚拟化与交互（已定）

- **虚拟化选 `@tanstack/react-virtual`**：唯一真叶子渲染器之一（`getScrollElement` 把滚动容器交给我们、`getVirtualItems` 还可视窗口），17.2M dl/wk、MIT、react 18 peer 兼容，**DSH 自己的轨迹视图也在用它**。实测增量 **+8,828 B gz-1**（总计约 102.6KB gz-1），在 25KB 天花板内。
- **行高按字符宽度预算**，不用 `measureElement`：等宽字体 + 容器宽度 + 便宜的宽字符（CJK）判断 ⇒ 高度是确定值，避开"变高行 + 追加"的滚动跳动类坑；且只在可见窗口那几十行上算，偏差不累积。
- **滚动启停**：常驻「跟随中 / 已暂停」开关（可点、可键盘操作）＋ 暂停且有积压时出现「↓ N 条新日志」pill（点击 = 跳到底 + 恢复跟随）。
- **暂停语义 = 连窗口一起冻结**：暂停期间新行**不进窗口**，只累计 `pendingCount` 与绝对序号；恢复时用一次 `read({from})` 补齐。暂停期间浏览器看不到新行，但**没有数据丢失**（宿主 ring + spool 都在），且**不需要新端点**。

## 第 1 步实现记录（2026-09-12）

七项（比原计划多一项，第 7 条是实测中发现的同源放大）：

1. `shown` → `useMemo`：原来每次渲染都重切一遍 2,000 槽（含零输出时的空转渲染）。
2. 行 key → **绝对序号** `seqBase + index`；`FilteredLine` 增加 `index` 字段承载「该行在缓冲里的下标」（滑动窗口的下标会整体前移，不能当 key）。
3. `setFromHistory`/`setTruncated` 移出 state updater（React 可能重复调用更新函数），改用 `logLinesRef` 镜像读当前缓冲。
4. offset **按配置记**（`offsetsRef: Map<runKey, number>`）：切回来不再整段重发；`start` 时把该配置的偏移归零（宿主 start 会把缓冲归零）。
5. 宿主 `snapshots()` **不再 drain**：采集交给 250ms 的 pump。依据：客户端每秒 1.25 次 × 每个配置一次 `Buffer.concat(≤64KB/流)`。
6. 宿主 ring 的丢弃改**批量**（`trimSlack = maxLines/10`）：饱和后不再每行搬移整个数组（摊还 O(1)/行，缓冲最多多留 10%）；小上限（测试里的 3 行）退化成逐行丢弃的老行为。
7. **额外**：轮询 effect 的依赖从 `active`/`activeConfig`（每次 `reload()` 都换身份的对象）改成 `[api, runKey, reload]`，目标配置走 `targetRef`；否则 effect 每 2.4s 重挂一次，而重挂会立刻多打一发 tick。

**空转实测（面板无进程在跑，10 秒窗口）**：`runs` **19 → 12** 次、`load` 6 → 4 次、单次响应最大 **673 B**（无 700KB 级重发）、帧 p50/p95/max = 16.7 / **17.4** / 17.8 ms。

**切换配置往返**：A(359 行) → B(616 行) → A(359 行)，内容不串不重。切回来时偏移已在 ring 末尾 → `read` 返回空 → 落回磁盘历史（上限 2,000 行），与「含上次运行的输出」标注语义一致。

**改了一条测试**：`test/host.test.mjs` 那条历史测试原来用 `runs()` 顺手触发 drain，现在改用 `read()`（按契约真正会采集的调用）。契约没变，只是不再依赖「读快照也有副作用」。

**未测**：流式追加时的帧时与常驻内存——需要一个正在输出的进程；不擅自启动你的 dev server，等有进程在跑时补测（或让性能脚本起一条临时配置，会写面板状态，需你点头）。

**界面上的一个小观察**：某些配置的历史首行是空行——查过了，是**文件里真实的空行**（那个 spool 文件首字节就是换行），不是读取器或本轮改动引入的。

## 追查"为什么显示已丢弃"（2026-09-12，用户提问引出）

**用户看到的**：`显示 8 / 共 8 行（缓存 8 行）（输出过快或过长，早期部分已丢弃）`——但根本没有丢数据。

**三个来源，两个在说谎**（提示词把三类完全不同的情况混成了一句）：

| 触发 | 真实含义 | 原提示词 |
| --- | --- | --- |
| `history.truncated` | 历史只取了最近 2,000 行（磁盘上还有更多） | 历史分支自己的措辞是对的 |
| `dropped` 且 `offset < base` | 环形缓冲（5,000 行）滚过，早期行不在内存 | 对 |
| `dropped` 且 `offset > next` | **进程重启后的重新同步**：整份重发，一行没丢 | **错**（冤枉自己丢日志） |
| `lossy`（shell 64KB 尾窗溢出） | 真丢字节 | 对 |
| 客户端缓冲超 4,000 行 | 真丢（内存里） | 对 |

**根因（比提示词更严重）**：历史兜底的触发条件写成了"**这一次读取没拿到新行**"，而那有两种含义——① 这一代进程从未产出过（兜底本意）；② **我已经追平、进程这几百毫秒没吐东西**（完全正常）。实测证据：宿主对 `read(from=0)` 回答 `lines:1005, next:1005, dropped:false, lossy:false`（一行没丢），而面板显示的是 2,000 行"上次运行的输出"——**它把已经拿到的实时行整段丢掉，换成了磁盘历史**，还打上了错误的"含上次运行的输出"标签。随后实时行恢复，历史让位给几行新输出，那个 `truncated` 标记没被重算 → 就出现了用户看到的 8/8 行 + "已丢弃"。

**修了三处（全部客户端，不动协议、不用重启）**：

1. 历史兜底的触发改成 `!historyTried && !sawLive`——`sawLiveRef` 只在**真的收到过实时行**时置位，切配置/启动时清零。
2. 历史让位给实时流时**重算**丢弃标记（`setTruncated(lost || over > 0)`），不再让历史的"只取了最近一段"串到实时视图。
3. 新增纯函数 `readLostLines(from, chunk)`（`rundisplay.ts`）+ 单测：把"重启重同步"和"环形滚过"分开，前者不再报丢。

**验证**：同一个正在跑的配置（zagent / HagueConfigWebApplication），修复前 `2000/2000 行（含上次运行的输出，只取了最近一段）` → 修复后 `1005 / 共 1005 行（缓存 1005 行）`，末行是实时尾。79 条测试 + 面板回归脚本全绿。

**留下的账**：`dropped` 的两种成因现在由客户端自己分辨（`from > next` ⇒ 重同步）。更干净的做法是宿主直接给两个字段（`resync` / `lost`），但那要动 schema + typert + descriptor 三处并重启 `dsh web`——留到第 2 步一起改。

## 快速跳到最新 + 跟随/暂停（2026-09-12，用户追加；第 4 步的第一件提前做了）

全客户端，不动协议、不用重启。

- 日志底部那行常驻「跟随中 / 已暂停」按钮（可点、可键盘操作）；上滚即暂停（沿用原来的 80px 贴底判定，但从看不见的 ref 变成显式状态）；暂停时按钮变成「↓ 跳到最新」，并显示暂停以来新到的行数；点它 = 跳到底 + 恢复跟随 + 计数归零。
- 顺手补了 `.ide-btn[data-on=true]` 的样式：此前只有属性没有 CSS，`⚙ 配置` 展开态也一直没有"已按下"的视觉反馈。

**两处实测发现（都不是猜的）**

1. **控件原本放右下角，被 whale-girl 桌宠盖住**——桌宠是固定定位，正好压在这个全高面板的角落（最早的用户截图里它也在压日志最后几行）。改成跟在统计文字后面靠左成组，统计文字可收缩省略、底栏单行不换行。
2. **布局变化会把用户的"暂停"悄悄解掉**：暂停时「↓ 跳到最新」出现 → 底栏换行 → 日志变矮 → `scrollTop` 被夹小 → 触发 onScroll → 当时"贴底即恢复"的规则立刻解除暂停。现在恢复跟随要求 `scrollTop` **确实在变大**（真的往下滚），被布局夹小的那种不算。

**验证（真机，zagent/HagueConfigWebApplication 正在产出）**

- 滚动事件记录仪：暂停后 12 秒内**零滚动事件**、状态稳定保持「已暂停」；
- 暂停期间新到 34 行 → 按钮显示「**↓ 跳到最新（34）**」；点它 → 回到「跟随中」、距底 0px、计数归零。

**未做（如实记账）**：批准的是 Q21 的「冻结」语义，这里**只做了计数+跳转，没有冻结**——暂停期间新行仍然进缓冲并渲染（实测 rows 345 → 379），所以长时间暂停时阅读位置可能被新行推走、最终被 4,000 行缓冲上限挤掉。冻结需要一个**便宜的积压计数**（宿主给 `next` 差值或专门字段），属于第 2 步的协议改动；现在这个计数是客户端按收到的行数累加的：**准确，但不省传输**。
