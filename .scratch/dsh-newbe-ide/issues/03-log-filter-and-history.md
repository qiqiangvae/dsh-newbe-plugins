# 03: 日志能用：过滤 + 落盘历史

**What to build:** 日志区能按关键字（含正则）、按 level（ERROR/WARN/INFO/DEBUG/OTHER）、按"仅看匹配"过滤，且过滤状态下仍然自动跟随；日志同时落盘，DSH 重启后还能翻到上一次跑的输出。

**Blocked by:** 02 (一条启动配置能一键启停，日志实时滚出来)

**Status:** ready-for-agent

- [x] 关键字过滤即时生效；「正则」开关切换后按正则解释，非法正则退回字面匹配且不报错
- [x] `仅看匹配` / `全部高亮` 两种模式可切换（命中行整行淡黄底）
- [x] level 徽章多选，任一关闭后对应行立即消失
- [x] 过滤开启时新到达的匹配行仍自动跟随；不匹配的行不打断跟随
- [x] 单条启动配置的日志达到环形上限后从头部丢弃，滚动不卡（环形 5000 行 + 单帧渲染封顶 2000 行）
- [x] 日志同时追加落盘到 `$DSH_HOME/storages/dsh-newbe-ide/logs/<项目>_<配置>.log`；DSH 重启后能读回上一次的输出（保留一代 `.1`，单文件上限 8MB）
- [x] 面板显示「显示 M / 共 F 行（缓存 N 行）」，补历史时标「含上次运行的输出」，截断有提示

## Comments

**实现记录（2026-09-12）**

- **过滤是纯函数**（`src/filter.ts`）：级别识别（FATAL→ERROR、TRACE→DEBUG）、关键字/正则匹配、过滤结果带 `hit` 标记。9 项测试覆盖大小写、非法正则退回、级别多选、空关键字、不改动原数组。
- **落盘**（`src/logsink.ts`）：每条启动配置一个文件，键经消毒（`../` 之类写不出去），追加写入、读尾部（只读最后 512KB）、超 8MB 轮转成 `.1`（只留一代：够回答"上次为什么挂"，又不会吃满磁盘）。6 项测试。
- **写入时机**：一次 drain 批一次写（不是一行一次），落盘失败不影响内存日志流。
- **历史读回**：内存缓冲为空且本轮进程没有输出时，客户端捞回落盘尾巴（2000 行）并标注「含上次运行的输出」；`start` 之后不再补历史（新进程输出从零开始）。宿主侧有端到端测试：进程输出 → drain → 落盘 → 新建 sink（模拟重启）仍读回同一份。
- **渲染封顶**：过滤是全量的，单帧最多渲染 2000 行，避免长日志拖慢面板。
- **一个用户可见的决定**：视图里出现了「过滤关键字」输入框。此前用户说过视图不该有输入控件，但那条针对的是配置表单与底部消息框；控制台搜索框是常规交互，已在提交信息与回复里说明，若用户不要可退化成只留级别徽章。
