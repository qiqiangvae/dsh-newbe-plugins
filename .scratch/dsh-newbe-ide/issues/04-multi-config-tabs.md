# 04: 一个项目多条启动配置：两层 tab

**What to build:** 一个项目 tab 下面挂多个启动配置 sub tab（如 `web`、`worker`），每条各自独立启停、独立日志、独立环境变量，互不影响；一级 tab 显示条数角标与聚合状态点。

**Blocked by:** 02 (一条启动配置能一键启停，日志实时滚出来)

**Status:** ready-for-human（实现完成，剩一次"双开两条配置"的点击验收）

- [x] 项目 tab 下渲染多个启动配置 sub tab，选中态清晰，二级 tab 独立一行
- [ ] 同一项目的两条启动配置可同时运行，各自日志互不串台；停掉一条不影响另一条
- [x] 一级 tab 显示启动配置条数角标，状态点为聚合（优先级：运行中 > 启动失败 > 已退出 > 已停止 > 未启动）
- [ ] 二级 tab 可新增、可删除（删除不影响其他配置的运行）——面板内的「⚙ 配置」块里操作
- [x] 头部显示当前启动配置的端口与运行时长，二级 tab 上也带端口；**PID 取不到**——DSH 的 shell 契约（`ShellProcess`）只有 status/exitCode/done/readOutput/kill/sandbox，不暴露 pid，见 Comments
- [x] 切换二级 tab 时日志区切换（本地缓冲清零、代次自增）、过滤条件保留（过滤是视图级状态）
- [x] 面板不注册任何全局方向键，因此不存在与输入框、日志滚动抢键的问题（原型里的变体切换键已随原型丢弃）

## Comments

**实现记录（2026-09-12）**

- **二级 tab 独立一行**：一个项目下的多条启动配置各占一格（圆点 + 名字 + 端口），末尾是「＋ 启动配置」；一级工具行不再塞配置 chip。
- **端口在宿主侧认**（`src/rundisplay.ts` 的 `parsePortFromLines`）：客户端只有当前配置的日志，拿不到别的配置的端口；宿主有每条配置的完整输出，因此逐行更新端口并放进快照。只认 `port <数字>` 这种明确写法——不拿裸冒号猜，时间戳里全是冒号，猜错比不显示更糟。
- **运行时长**：宿主在启动时记 `startedAtMs`，客户端用 `formatUptime` 出文案（时钟回拨不显示负数）。面板每 800ms 重绘一次，所以时长自己会走。
- **聚合状态**：`aggregateStatus` 按"需要注意"排序；只要有一条在跑，一级 tab 就是绿的。
- **测试**：新增 6 项纯函数测试（时长文案含时钟回拨、端口识别含"不猜时间戳"、聚合优先级），共 75 项全绿。
- **仍未验证（留给用户一次点击）**：两条配置同时运行、停掉一条另一条不受影响、各自日志不串台——机制层已由运行注册表的测试覆盖（每个 key 一个进程与一份缓冲），但真机双开需要点一次。
